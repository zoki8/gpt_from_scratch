# GPT from scratch

A small GPT written from scratch in PyTorch and trained on Shakespeare. The project builds up one piece at a time: a character tokenizer first, then a bigram model, self-attention, multi-head attention, feed-forward layers, transformer blocks with residual connections and LayerNorm, dropout, a bigger model trained on a GPU, a faster batched attention, and a BPE tokenizer written from scratch. A script for fine-tuning the pretrained GPT-2 on the same text is included for comparison.

## Sample

Generated by the trained model (4.8M parameters, BPE tokenizer) with no prompt:

```
MENENIUS:
Then know, you are well.

First Citizen:
Welcome; but hear them speak.

Third Citizen:
No, master,
That's no stronger. Can you see, pray you?

BRUTUS:
See now, my soul!
```

The model writes one token at a time and was trained only on `data/input.txt`. Generated lines checked against the training text do not appear in it.

## Results

Validation loss on the last 10% of the text, which the model never trains on. Lower is better. To compare models with different tokenizers, the loss is given per character (cross-entropy per token divided by the average number of characters per token).

| Model | Tokenizer | Parameters | Val loss per character |
|---|---|---:|---:|
| Bigram (lookup table) | characters | 4K | 2.49 |
| 1 attention head | characters | 7.5K | 2.44 |
| 4 attention heads | characters | 7.5K | 2.32 |
| + feed-forward | characters | 16K | 2.26 |
| 3 blocks, residual connections, LayerNorm | characters | 42K | 2.16 |
| 4 blocks, 128 embd, 64 context, dropout 0.1 | characters | 0.8M | 1.56 |
| 6 blocks, 256 embd, 128 context, dropout 0.2 | characters | 4.8M | 1.53 |
| **Same model** | **BPE, 512 tokens** | **4.8M** | **1.49** |

A loss of 1.49 per character means the model gives the correct next character about 23% probability on average (e^-1.49), compared with 1.5% for random guessing among 65 characters (ln 65 = 4.17).

BPE makes the text 2.17 times shorter, so a context of 128 tokens covers about 280 characters. It also overfits faster: the best validation loss (about 1.43 per character) was reached at step 3000 of 5000, after which validation loss rose while training loss kept falling. The 1 MB of Shakespeare is the limit here, not the model size.

The 4.8M model trains in about 9 minutes on an NVIDIA RTX 2050 (4 GB). Computing all attention heads in one call to `F.scaled_dot_product_attention` made training about 1.5 times faster than the per-head version and lets a 10.8M model (384 embd, 256 context) fit in 4 GB.

## Files

| File | What it does |
|---|---|
| `tokenizer.py` | `CharTokenizer` (one token per character) and `BPETokenizer` (byte pair encoding: learns merges of frequent pairs, then encodes new text by applying them in order) |
| `bpe.json` | The learned BPE vocabulary (65 characters + 447 merges), so it is not retrained on every run |
| `data.py` | Loads `data/input.txt`, picks the tokenizer (`TOKENIZER = 'bpe'` or `'char'`), splits 90/10 into train and validation, and samples random batches with `get_batch` |
| `model.py` | `Head` and `MultiHeadAttention` (the original per-head attention), `CausalSelfAttention` (all heads at once), `FeedForward`, `Block`, `BigramModel`, and `AttentionModel` (the GPT) |
| `train.py` | Hyperparameters, the training loop, loss estimation, and saving the model and its tokenizer to `model.pt` |
| `generate.py` | Loads `model.pt` and writes new text from a prompt |
| `attention_playground.py` | Small experiment showing how a triangular matrix averages past tokens, the trick behind masked attention |
| `finetune_gpt2.py` | Fine-tunes the pretrained GPT-2 (124M parameters) on the same text, printing samples before and after |
| `lora.py` | LoRA written from scratch: `LoRALinear` freezes a layer and learns a low-rank update `B @ A` (B starts at zero, so training starts from the original model); `apply_lora` wraps GPT-2's attention layers |
| `finetune_lora.py` | Fine-tunes GPT-2 medium (355M parameters) with LoRA: 786K trainable parameters (0.22%), frozen weights in bfloat16, saves only the 3 MB adapter to `lora_medium.pt` |

## Model

```
tokens → token embedding + position embedding
       → 6 × Block [ x + CausalSelfAttention(LayerNorm(x)),  x + FeedForward(LayerNorm(x)) ]
       → LayerNorm → Linear → scores for the next token
```

- Masked self-attention: each position only sees earlier positions.
- 4 heads per block, computed together from one query/key/value projection.
- Feed-forward: Linear (256 → 1024), ReLU, Linear (1024 → 256).
- Dropout 0.2 on attention weights and on each block's outputs.
- AdamW, learning rate 3e-4, batch of 64 sequences of 128 tokens, 5000 steps.

## Running it

Set up the environment:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`requirements.txt` installs the CPU build of PyTorch. To train on an NVIDIA GPU, install a CUDA build that matches your driver, for example:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu130
```

Train (uses the GPU automatically if PyTorch can see one, and saves `model.pt`):

```bash
python train.py
```

Generate text from the saved model:

```bash
python generate.py "ROMEO:" 400 0.8
```

The three arguments are the prompt, the number of tokens to write, and the temperature. Lower temperature (0.5) gives safer, more repetitive text, and higher temperature (1.5) gives more varied but messier text. Without arguments it starts from a new line and writes 500 tokens at temperature 1.0. The prompt can only use characters that appear in the training text.

To use the character tokenizer instead of BPE, set `TOKENIZER = 'char'` in `data.py` and train again. To learn a different BPE vocabulary, change `BPE_VOCAB_SIZE` and delete `bpe.json`.

`model.pt` is not in the repository (`*.pt` is in `.gitignore`), so run `train.py` once before `generate.py`.

### Fine-tuning GPT-2

```bash
python finetune_gpt2.py
```

This downloads GPT-2 (about 550 MB) on the first run, prints a sample before training, fine-tunes for 500 steps with a small learning rate (5e-5) using bfloat16 autocast so it fits in 4 GB, and prints a sample after. The fine-tuned model is saved to `gpt2-shakespeare/`, which is not in the repository. This script has not been run yet, so there are no results for it in the table above.

### LoRA on GPT-2 medium

```bash
python finetune_lora.py
```

Full fine-tuning of GPT-2 medium would need about 4.3 GB just for gradients and AdamW state, more than the 4 GB card has. With LoRA (rank 8 on every attention `c_attn` layer) only 786K parameters are trained, so the frozen 355M-parameter model fits in bfloat16 with gradient checkpointing. Before any fine-tuning, GPT-2 medium already reaches a validation loss of about 1.16 per character on this text, because it already knows English (and has likely seen Shakespeare during pretraining); its samples are modern English prose, not play dialogue. A full 500-step run has not been done yet.

## Data

`data/input.txt` is the Tiny Shakespeare dataset: about 1.1 million characters from Shakespeare's plays.
